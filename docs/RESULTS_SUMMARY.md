## 3. Training configuration (identical for LoRA and QLoRA)

- Base model: `Qwen/Qwen2.5-0.5B-Instruct`; max sequence length 512; train/val size 840/180.
- LoRA: r=16, alpha=32, dropout 0.05, target modules q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj.
- Optimisation: 3 epochs, lr 0.0002, cosine schedule, warmup 16 steps, batch 4 × grad-accum 2, fp16, loss only on the answer tokens.
- LoRA fp16: full-precision fp16 base, `adamw_torch`, gradient checkpointing. QLoRA: 4-bit NF4 base with double quantization (compute fp16), `paged_adamw_8bit`.
- Deployed artefact: the QLoRA adapter merged into an fp16 copy of the base (`rachitst/oncall-ai-incident-classifier`, model.safetensors 988 MB).

## 10. Observations and limitations (from the runs above)

- Both LoRA and QLoRA reach 1.000 on the synthetic test set; the merged QLoRA model reproduces 1.000 type / 0.983 severity accuracy on 60 logs. The rules baseline is strong on type (0.872) but weak on severity (0.683); the un-tuned 0.5B model is near chance; the 27B cloud model is good but not perfect (0.944 / 0.800) and costs a network round trip plus rate limits.
- Hand-written sample 03 (TLS expired, prod, '100% of requests failing') is classified **tls_certificate_expired P2** by the fine-tuned model although the policy expects P1: the generator's P1 wording ('error rate NN% across all N hosts', 'all users', 'primary database unavailable') never uses that phrase, so this is a distribution-shift miss of the synthetic data, visible only outside the test set.
- Sample 07 (INFO noise only) gets a confident wrong type from the fine-tuned model (no 'unknown' class); the grounding check in the `verify` node catches it (ungrounded → needs human review), which is why the workflow has that node.
- Groq free tier allows 8,000 tokens/minute and 200,000 tokens/day per model. After the Colab baseline and repeated smoke tests the 27B model's daily quota was exhausted, so the backend now switches to `LLM_FALLBACK_MODEL` (openai/gpt-oss-120b) on a per-day 429; the smoke tables above were produced with that fallback active (the answering model is recorded in `analysis.model`). Per-minute 429s are retried honouring Retry-After (≤30 s, 2 retries).
- Hugging Face Spaces refused a Docker Space on the free CPU tier (PRO required), so the live demo runs on Modal with the same container definition; the Dockerfile and `scripts/deploy_space.py` remain for a PRO account.
